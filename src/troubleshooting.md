# 困ったときは

> **Note**\
> このページは2026年12月の研修に向けて編集中です。内容は変更されることがあります。

研修の当日に進行が止まりやすい症状と、その対処をまとめます。
画面に表示されたメッセージやエラー名から、該当する症状を探してください。
詳しい説明はリンク先の章にあります。
解決しない場合は、表示されたメッセージを控えて講師に相談してください。

## どのサンプルにも共通すること

### HTMLファイルをダブルクリックして開いた

- **確かめること**：アドレスバーが`file://`で始まっていないか。
- **対処**：`npm start`で起動した`http://localhost`のURLで開き直します。サンプルは`<script type="module">`で読み込むので、`file://`ではスクリプト自体が読み込まれません（[サンプルの動かし方](web-serial/index.md#サンプルの動かし方)）。

### 埋め込みの画面で選択画面が開かない

- **確かめること**：教材のページに埋め込んだ画面で操作していないか。
- **対処**：サンプルのバッジから、別のタブで開きます。

## Prompt API

### `LanguageModel.availability()`が`"available"`にならない

- **確かめること**：返った値が`"downloadable"`、`"downloading"`、`"unavailable"`のどれか。`LanguageModel`がなく`ReferenceError`になる場合もあります。
- **対処**：値ごとの対処は[受講環境の事前確認](prompt-api-setup.md#うまくいかないとき)の表に従います。`"unavailable"`なら、ストレージ、GPU、メモリの要件を確認します。

### モデルのダウンロードが始まらない、進まない

- **確かめること**：Chromeのプロファイルがあるドライブに22GB以上の空きがあるか。テザリングなど従量課金の回線を使っていないか。
- **対処**：空き容量を確保し、従量課金でない回線につなぎます。`chrome://on-device-internals`で、ダウンロードの状況と端末の判定結果を確認できます（[受講環境の事前確認](prompt-api-setup.md#ストレージ)）。

### `LanguageModel.create()`で`NotAllowedError`が出る

- **確かめること**：モデルが未ダウンロードのまま、ページの読み込み時など、ユーザー操作の外で呼び出していないか。
- **対処**：ボタンの`click`イベントの中で呼び出します（[Prompt API入門](prompt-api.md#セッションを作成してプロンプトを送る)）。

## WebLLM

### 「WebGPUを利用できません」と表示される

- **確かめること**：WebGPUに対応したブラウザで、`https://`か`http://localhost`のページを開いているか。
- **対処**：対応したブラウザで開き直します。このサンプルはWebGPUが必須で、使えない端末では実行を止めます（[WebGPUとの関係](webassembly.md#webgpuとの関係)）。

### モデルの読み込みや生成の途中でエラーになる

- **確かめること**：通信が切れていないか。GPUメモリを使う他のアプリが動いていないか。
- **対処**：通信とブラウザのGPU設定を確認し、GPUメモリを使うアプリを閉じてから再度実行します。初回はライブラリとモデル（約0.3GB）を取得するため、会場の回線では時間がかかります（[コードの要点](webassembly.md#コードの要点)）。

## ファイル保存

### ファイル選択画面が開かない

- **確かめること**：ボタンのクリックから開いているか。モデルの推論などを待ってから開いていないか。
- **対処**：選択画面は、クリックなどの操作から開きます。推論の後に開くと操作の有効期間が切れる場合があるため、選択画面を先に開きます（[JSONファイルへの保存](file-system.md#jsonファイルへの保存)）。

### `SecurityError`でファイル選択画面が開かない

- **確かめること**：LiveCodesやStackBlitzの画面で動かしていないか。これらのエディターはサンプルを別オリジンのiframeの中で実行するため、ファイル選択画面を開けません。
- **対処**：OPFSに保存するか、`npm start`で起動した`http://localhost`のページで試します（[保存先を選ぶ方法とアプリ内に保存する方法](file-system.md#保存先を選ぶ方法とアプリ内に保存する方法)）。

### OPFSに保存した記録が見つからない

- **確かめること**：保存したときと同じURLで開いているか。ポート番号が変わっていないか。
- **対処**：同じURLから開き直します。`http://localhost:3000`と`http://localhost:3001`は別のオリジンなので、保存領域も別です。未保存のファイルを読み込むとエラーになります（[保存先を選ぶ方法とアプリ内に保存する方法](file-system.md#保存先を選ぶ方法とアプリ内に保存する方法)）。

### 前に保存したファイルの内容が消えた

- **確かめること**：保存先に既存のファイルを選ばなかったか。
- **対処**：既存のファイルを選ぶと内容を置き換えます。演習用の名前で保存します。

## Web SerialとCore2

### ポートの選択画面にCore2が出てこない

- **確かめること**：USBシリアル変換チップ用のドライバー（CP210XまたはCH9102）をインストールしたか。候補が複数あるときは、どれがCore2か。
- **対処**：ドライバーをインストールします（[UIFlow2を書き込む](web-serial/m5stack-setup.md#uiflow2を書き込む)）。候補が分からないときは、Core2のケーブルを抜き差しして、消えたり現れたりするポートを選びます（[センサー値をブラウザでモニターする](web-serial/sensor-monitor.md#動かしてみる)）。

### 「接続できませんでした」と表示される

- **確かめること**：UIFlow2のタブや、別のサンプルのタブが、同じポートを開いたままになっていないか。選択画面を閉じた場合は`NotFoundError`になります。[センサーと音声をPrompt APIでつなぐ](web-serial/sensor-assistant.md)のサンプルでは、「接続または受信を終了しました」と表示されます。
- **対処**：ポートを開いているタブを閉じてから、もう一度「接続」（または「Core2に接続」）を押します。シリアルポートを同時に開けるのは1つのページだけです（[ブリッジのプログラムを書き込む](web-serial/m5stack-setup.md#ブリッジのプログラムを書き込む)）。

### 操作していないのに「切断されました」と表示される

- **確かめること**：USBケーブルが抜けていないか。サンプルによっては「切断しました」「接続または受信を終了しました」と表示されます。
- **対処**：ケーブルをつなぎ直し、もう一度接続します。

### サーボモーターが動かない

- **確かめること**：サーボモーター用の5V電源を入れたか。GNDをCore2と共通にしているか。`ping`の応答が`"channels": 2`か（[サーボモーターを動かす](web-serial/servo.md)のサンプルでは「ブリッジが動かせるサーボは1個です」と表示されます）。
- **対処**：電源とGNDの配線は[サーボモーターを配線する](web-serial/m5stack-setup.md#サーボモーターを配線する)で確認します。`"board": "unknown"`と`"channels": 1`が返る場合は、ブリッジの`BOARD`を指定して書き込み直します（[動作を確かめる](web-serial/m5stack-setup.md#動作を確かめる)）。

### サーボモーターが「ジー」と鳴る、熱くなる

- **確かめること**：関節が届かない角度を指示していないか。
- **対処**：「脱力させる」を押してから、可動範囲を記録し直し、`JOINTS`の`min`と`max`に反映します（[可動範囲を確かめる](web-serial/servo.md#可動範囲を確かめる)）。

### サーボモーターが動いた瞬間にCore2が再起動する

- **確かめること**：サーボモーターの電源をCore2から取っていないか。
- **対処**：Core2とは別の5V電源につなぎます。複数のサーボモーターが同時に動くと大きな電流が流れます。

### `"env": false`が返る、Core2の画面が「ENV: -」のまま

- **確かめること**：ENV ⅢをPort A（赤いGrove端子）に挿しているか。
- **対処**：Port Aに挿し直します。ENV Ⅲは必須ではなく、つないでいなくてもブリッジは動き続けます（[温湿度センサーを配線する](web-serial/m5stack-setup.md#温湿度センサーを配線する)）。

## 音声認識

### `"not-allowed"`、`"audio-capture"`のエラーが出る

- **確かめること**：マイクの使用を許可したか。マイクがつながっているか。
- **対処**：マイクをつなぎ、使用許可を求められたら許可してから、もう一度開始します。他のエラーの意味は[エラーへの対処](web-serial/speech-recognition.md#エラーへの対処)の表で確認します。

### `"language-not-supported"`のエラーが出る

- **確かめること**：「端末内で処理する」を選んでいないか。`SpeechRecognition.available()`の結果が`"available"`か。
- **対処**：言語パックがない状態で端末内の認識を指定すると、このエラーになります。端末内の認識をやめるか、言語パックをダウンロードします（[音声が処理される場所](web-serial/speech-recognition.md#音声が処理される場所)）。

### `"network"`のエラーが出る

- **確かめること**：ネットワークに接続しているか。
- **対処**：Chromeの音声認識は、既定ではサーバーで処理するため、ネットワークへの接続が必要です。接続を確かめてから、もう一度開始します。

### 音声認識がどうしても使えない

- **確かめること**：テキストの入力欄があるか。
- **対処**：同じ指示を文字で入力して送信します。[声でサーボモーターを動かす](web-serial/voice-servo.md#動かしてみる)と[センサーと音声をPrompt APIでつなぐ](web-serial/sensor-assistant.md)のサンプルは、文字の入力でも同じ処理を行います。
